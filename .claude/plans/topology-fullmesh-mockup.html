READING THE MOCKUP

  • Self node — glowing green; the node rendering the page.
  • Mesh peer — cyan stroke; every node batadv-vis/Alfred has a publication for.
  • Solid cyan edge — an RF link between two mesh peers (intra-segment).
  • Dashed amber edge — a BLOS (vxlan0) bridge between segments.
  • Client badge — the small ·N chip next to a node = count of non-mesh clients attached (transtable entries in the vis payload). Individual client MACs are not rendered.
  • MY PATHS toggle — off by default (State 1). When on (State 2), edges on my originator best-route tree render full-opacity + drop-shadow; every other mesh edge dims to ~18 % opacity so it stays visible as context but doesn't compete.

WHAT THIS SOLVES

  • In State 1, the triangle (alpha ↔ bravo and bravo ↔ charlie) and the remote cycle (pr-E ↔ pr-F, pr-F ↔ pr-G) are visible. The current production page would render none of those — only my three direct-neighbor edges and my single BLOS edge. The operator now sees actual field connectivity.
  • In State 2, the per-node "how do I reach X" story is still recoverable via the toggle. Nothing is lost; the default just leads with mesh reality.

DATA-SOURCE FIT CHECK

  • Node primary MACs + secondaries → direct from vis[].primary/vis[].secondary.
  • Hostnames → joined from /tmp/bat-hosts (existing lookup).
  • Edges → from vis[].neighbors[{router,neighbor,metric}].
  • Segment (LOCAL vs REMOTE MESH) → from our originator table (batctl oj): a node is REMOTE if any of its MACs appears with hard_ifname=vxlan0.
  • "On my path" flag → match edge (router,neighbor) against our originator table's (orig,best_next_hop) pairs.
  • Client badge → length of vis[].clients.
